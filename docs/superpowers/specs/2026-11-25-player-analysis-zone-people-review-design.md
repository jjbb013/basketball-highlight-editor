# 人物分析区与人物复核页设计

日期：2026-11-25  
分支：`feature/player-analysis-zone-people-review`  
状态：用户已确认采用方案一

## 1. 背景与目标

现有导入流程包含橙色“投篮分析区”和白色“篮网检测区”；人物身份识别目前复用投篮分析区的扩展范围，人物证据只在单个候选详情中以小入口展示。用户要求：

1. 增加第三个“人物分析区”，让人工明确指定需要重点观察的人物范围。
2. 增加独立的人物分析页面，按身份集中展示识别结果。
3. 页面必须支持人工命名、单条修正、查看同身份候选，并保持自动结果可复核。

## 2. 推荐方案

采用“可选紫色人物分析区 + 审核页内人物复核页”。不新增全局侧边栏，避免扩大项目导航和恢复状态；人物复核仍属于审核流程，但拥有独立页面视图。

## 3. 人物分析区

### 3.1 交互

- 导入页现有区域切换从两项扩展为三项：
  1. 投篮分析区（橙色）；
  2. 篮网检测区（白色）；
  3. 人物分析区（紫色）。
- 人物分析区是可选区域，不作为新的必填步骤。
- 未设置人物分析区时，界面显示“沿用投篮区扩展范围”，分析行为与旧版本一致。
- 用户点击人物分析区后可以拖动或缩放；也可以恢复默认。
- 多段视频沿用当前段配置；跨段复制时与投篮区和篮网区一起复制。

### 3.2 数据

人物区域保存到当前视频 ROI 的 `calibration_json`：

```json
{
  "person_roi": {"x1": 0.0, "y1": 0.0, "x2": 1.0, "y2": 1.0},
  "person_roi_source": "manual"
}
```

坐标使用与 `net_roi` 相同的源像素坐标。第一版不新增数据库表，不需要迁移；旧项目没有该字段时继续走原逻辑。

### 3.3 分析行为

- 投篮检测和篮网复核继续只使用原有投篮区与篮网区，不受人物区影响。
- 人物检测、最后触球分析和外观特征分析按以下优先级选择范围：
  1. 用户设置的有效 `person_roi`；
  2. 现有 `expanded_roi(投篮分析区)`。
- `person_roi` 必须与画面有有效交集，并且宽度、高度均不得低于最小阈值。
- 无效、越界或退化的人物区不阻断分析；记录诊断日志并回退到投篮区扩展范围。
- 人物区过小可能导致漏识别，因此导入页在保存时提示，而不是直接失败。

## 4. 人物复核页

### 4.1 入口

审核页顶部增加“投篮／人物”分段切换：

- **投篮**：现有候选审核、片段调整和篮网球复核。
- **人物**：新的人物分析页。

该入口只在当前项目已经加载后显示。分析中仍可打开页面查看已有结果，但写操作沿用现有忙碌状态和项目加载代际保护。

### 4.2 数据组织

人物页直接消费 `projectProvider` 中现有 `list_candidates` 数据，按 `identity_id` 分组：

- 有身份证据的候选进入对应身份组；
- 没有身份证据的已标记候选进入“未生成人物证据”分组；
- 未标记且无身份证据的候选不在页面中抢占主视图，但提供筛选开关显示。

每组显示：

- 身份名称：已命名球员名或“未命名身份”；
- 候选数量；
- 自动、待复核和人工修正数量；
- 身份置信度范围或当前候选置信度；
- 是否人工标记优先。

组内候选卡片显示：

- 片段时间与视频来源；
- 最后触球时间；
- 触球置信度和身份置信度；
- 自动推测／待复核／人工标记优先状态；
- 当前球员名；
- 片段预览（已有候选预览可用时展示）。

### 4.3 操作

- **命名此身份**：调用现有 `name_identity`，把同一身份的自动候选批量同步为同一球员；人工指定候选不覆盖。
- **修正此片段**：复用现有 `set_candidate_player`，允许选择已有球员或新建球员；写为人工来源。
- **清除人工修正**：对人工候选清除标签，仍保留身份证据供重新复核。
- **查看投篮片段**：跳转回投篮审核并选中对应候选。
- **只看待复核／只看人工／显示无证据候选**：页面内筛选。

### 4.4 状态语义

- 自动结果必须明确标注“自动推测”或“身份待复核”。
- 身份页不显示“准确率”，只显示算法给出的置信度和证据状态。
- 页面Tooltip继续说明这是同场外观与最后触球关联，不是跨天生物识别。

## 5. 数据流与错误处理

```text
导入页 person_roi
  → save_roi calibration_json
  → start_analysis checkpoint
  → service 读取有效 person_roi 或回退 expanded shot ROI
  → identify_players 输入与缓存 key 使用人物分析范围
  → candidate_player_assignments / player_identities
  → list_candidates 返回身份证据
  → 人物复核页分组、命名和单条修正
```

错误处理保持以下边界：

- 保存人物区失败：提示并保留本地编辑，不静默丢弃。
- 人物区无效：导入页提示；分析端回退到投篮区扩展范围。
- 人物模型不可用：与现有实现一致，不删除投篮候选，只报告人物证据不可用。
- 命名失败：显示现有统一错误提示，不局部修改候选列表。
- 切换项目或关闭项目时，人物页中止未完成写操作并沿用现有代际保护。

## 6. 测试

1. Flutter 单元／组件测试：
   - 三项区域切换和人物区默认状态；
   - 保存、恢复、重置人物区；
   - 审核页“投篮／人物”切换；
   - 身份分组、候选计数和筛选；
   - 命名身份、单条修正、清除修正、跳转投篮审核；
   - 旧项目无 `person_roi` 时正常打开。
2. Python Engine 测试：
   - `calibration_json.person_roi` 解析与坐标校验；
   - 有效人物区进入人物识别命令与缓存 key；
   - 无效人物区回退投篮区扩展范围并记录日志；
   - 投篮区和篮网区行为不因人物区改变。
3. 协议测试：`save_roi` 继续接受旧 payload，新增 `person_roi` 时保留旧字段。
4. 本地化：新增中英文文案并测试回退。
5. 回归：现有投篮审核、导出、人物命名传播和跨项目导出测试全部通过。

## 7. 非目标

- 不承诺跨比赛自动人脸识别。
- 不在第一版新增人物合并、拆分或人工训练模型。
- 不改变现有投篮候选生成、篮网复核和导出配置。
- 不新增 Apple 公证、自动更新或新 Release；本次先提交分支与 README。
