# macOS 球员身份识别与增强导出设计

日期：2026-11-23  
基线：`cb8de11`  
分支：`feature/macos-player-identity-enhanced-export`  
状态：按用户授权自动实施，关键取舍另见开发 Review 文档。

## 1. 目标与边界

在现有 Flutter 桌面应用和 Python Engine 上增量实现：

1. 交付 Apple Silicon 与 Intel Mac 的 DMG。
2. 导出时可添加人物标签封面；默认开启、3 秒，可关闭；内置多种样式并支持本地自定义。
3. 导出时可添加运动背景音乐；默认使用原音量的 20%，保留现场声；内置多种类型并支持本地音乐。
4. 不依赖球衣号码，在本场视频内检测人物、提取外观特征、跟踪最后触球者，将进球归入可命名身份。
5. 为一个身份命名后，同身份的自动归属候选批量更新；人工指定的候选不被批量操作覆盖。
6. 多选历史项目，将不同日期中同名球员的候选一起导出。

非目标：不承诺无标注情况下的跨天 biometric 识别，不把现成 COCO Pose 权重描述为本项目训练的球员模型，不在没有人工真值时宣称准确率。

## 2. 总体方案

保留以下现有边界：

- `apps/desktop`：项目/身份选择、封面和音乐设置、识别证据复核。
- `engine/python/basketball_engine`：SQLite、协议、任务检查点、只读项目快照与导出编排。
- `src/basketball_highlight`：YOLO 适配、短时跟踪、外观特征、最后触球和身份聚类。
- `adapters/export.py`：精确剪辑与混流；新增独立增强模块负责封面和 BGM。
- 现有 GitHub Actions macOS runner：构建和发布 DMG。

身份识别是“本场可保存、可纠正的身份模型”，而不是一个未训练的通用识别器。检测使用现有篮球模型与 YOLO Pose；在候选前的小时间窗工作，缓存检测与特征，避免扫描整段长视频。

## 3. 最后触球者识别

### 3.1 输入与检测

每个保留候选使用进球锚点、篮筐尺寸、已有球轨迹及进球前最多 6 秒的代理帧。时间窗在投篮动作不完整时可调，默认采样 15 fps；只对局部窗口追加检测，不重复分析整场。

YOLO Pose 输出人物框和手腕等关键点；现有 ball/hoop 模型输出球和篮筐。检测器通过统一适配接口返回：

```text
FrameObservations(time_ms, persons[], balls[])
PersonObservation(local_track_id, bbox, keypoints[], detection_confidence)
BallObservation(center, radius, detection_confidence)
```

跟踪 ID 仅在一次短时窗口内有效，不作为跨窗口身份。人物框关联使用位置、尺度、外观向量和轨迹连续性；遮挡后不强制连接。

### 3.2 触球判定

以倒序球轨迹为主线，对每个可见人物执行：

1. 用 Pose 左右手腕和人物躯干尺度求球—手腕归一化距离；关键点被遮挡或低置信度时该帧不参与正证据。
2. 将球进入手部区域的连续帧组成接触段，而非使用单个噪声帧。
3. 检查接触后球离手、球路连续且总体朝向篮筐；没有离手段的站人近球、篮板球或传球不误判为本次投篮。
4. 从进球向前回溯，选择满足释放条件的最后一个接触段。该段对应人物为候选投篮者。
5. 结合接触时间、距离、球速/方向连续性、人物检测质量和跟踪稳定性形成 `touch_confidence`。

证据至少保存 `touch_time_ms`、局部轨迹 ID、接触窗口、球与手腕相对位置、算法版本和置信度。分数仅用于排序和复核，不当作统计准确率。

以下情况输出未归属并请求复核：没有可见接触段、前两名间隔过小、人物严重重叠、球轨迹中断、投篮发生在窗口之前，或身份相似度不足。自动结果不能替代确定的人工标签。

### 3.3 身份特征与模型

对同一个人物的多个清晰观测进行质量加权，提取：

- 头部/发型区域的形状比例、亮度与颜色分布；
- 可见皮肤的颜色分布，按光照做相对归一化；
- 脸部区域的轮廓和长宽等弱特征，不声称跨天人脸识别；
- 上衣、下装、鞋袜的颜色与纹理分布；
- 相对身高和体型比例，不推算真实身高或敏感属性。

同一帧低清晰度、逆光、过小人框和严重遮挡降低对应权重。特征向量附带有效区域掩码，比较时只在双方有效维度上计算距离。

本场模型由版本化观测原型、聚类中心和身份样本计数组成，存于项目私有数据，不进入 GitHub。先形成稳定身份簇，再用新增观测增量更新；命名是簇到 `players` 的映射，不改变原始证据。人工拆分/合并身份是后续纠错入口。

建议第一版阈值通过本地验证集校准；在未测量前不硬编码“95%”等承诺。身份结果同时保存 `identity_confidence` 与第二名差值。

## 4. 数据模型与命名传播

新增概念：

- `player_identities`：项目内身份 ID、所属项目、可选球员 ID、模型版本、原型 JSON、样本数、时间戳。
- `candidate_player_assignments`：候选 ID、身份 ID、可选球员 ID、触球证据、身份置信度、来源（`automatic` / `manual`）、算法版本、时间戳。

`candidate_reviews.player_id` 继续作为 UI 展示与现有人工流程的有效标签。新增表保存推断证据和人工覆盖状态，不把 JSON 塞进文件名或公开日志。

规则：

1. 自动分析只写/更新 `automatic` 归属。
2. `set_candidate_player` 把对应记录标成 `manual`，用户清除标签也构成明确人工覆盖。
3. 命名身份时，事务内创建/查找球员，更新身份映射，再批量更新该身份下未人工覆盖的候选。
4. 批量更新跳过其他身份和已人工指定的候选；返回更新数量供 UI 展示。
5. 重新分析沿用稳定证据/身份映射，不删除人工决定。
6. 删除身份只清除自动归属，不删除真实球员和人工标签。

SQLite 采用增量兼容迁移，旧项目可打开。公开 SQL 架构和运行时迁移保持一致。

## 5. 封面与 BGM

### 5.1 配置

每次导出快照保存不可变配置：

```json
{
  "cover": {
    "enabled": true,
    "duration_ms": 3000,
    "style": "court",
    "title": null,
    "subtitle": null,
    "background_path": null,
    "accent_color": "#F97316"
  },
  "audio": {
    "enabled": true,
    "track": "electronic_drive",
    "custom_path": null,
    "volume": 0.2
  }
}
```

封面时长允许 0–10 秒；`enabled=false` 时不添加。BGM 音量限制在 0–1，默认 0.2。空标题按输出上下文生成：按球员导出使用球员名，普通合并使用“进球集锦”，单段导出使用已有标签或通用标题。

### 5.2 内置样式与自定义

第一版内置：

- `court`：暖色篮球场线条、人物名和进球集锦；
- `poster`：大字号杂志排版、色块与日期；
- `photo`：从本地选择的背景图生成全幅封面，带可读性遮罩。

自定义支持标题、副标题、强调色和背景图。人物证据裁图只在本地使用，默认不自动公开球员照片。模板由 Pillow 输出与视频同尺寸的 RGB PNG，处理中文字体回退和超长名字。

### 5.3 音乐

内置三类项目内生成并可再分发的原创循环音乐：电子驱动、嘻哈律动、摇滚脉冲；生成源脚本和授权说明随源码保存。用户可选择本地音频作为自定义 BGM。音乐不是从参考成片抽取，避免复制其音轨权利。

### 5.4 合成与失败语义

先执行现有精确剪辑/合并，再对每个最终输出独立后处理；合并模式不会为每个内部片段重复加封面。封面视频和原片段统一分辨率、帧率、SAR 与时间基。

音频统一为 48 kHz 立体声：现场声保持 1.0，BGM 循环并乘 `volume`，`amix` 使用 `normalize=0`，避免现场声被自动压低；无现场声时补静音。封面阶段仍播放 BGM。输出 AAC/H.264，沿用现有编码器回退与取消机制。

所有增强写临时文件，探测视频/音频及总时长成功后原子替换；失败删除新产物并保留原始导出。配置进入任务 checkpoint，重试不会重复添加封面或叠加 BGM。

## 6. 跨项目导出

项目选择器可添加多个已有项目目录。外部项目通过 SQLite `mode=ro` 打开；只读连接不执行建表、迁移或 WAL 写操作，也不复制原视频。

导出快照为每条候选携带：来源项目 ID/名称、视频 ID、源路径、源大小/mtime/fingerprint、视频尺寸/fps/音频信息、片段边界、球员名和效果证据。当前项目和外部项目使用相同校验。

跨项目合并键为去除首尾空白、统一 Unicode 大小写的姓名；只在本次导出中分组，不批量改写历史项目。同名不同人可在选择阶段排除；不同名字不会凭外观自动合并。未命名身份仍限定在原项目内，避免不同比赛的“身份 1”混成一人。

任务只消费启动时快照；源丢失、变更或外部项目身份变化时失败并清理新文件。沿用目标不得覆盖源视频、原子发布、磁盘预检与任务恢复语义。

## 7. UI 与协议

- 审核页显示自动身份、最后触球时间、置信状态和证据；提供“命名此身份”和单条人工改派。
- 导出页新增项目多选、按同名球员筛选、封面开关/时长/样式/自定义、BGM 开关/类型/试听/自定义和音量。
- 自动归属必须可识别为推测；低置信度默认显示待复核，不伪装成人工确认。
- 协议请求由 schema 校验；绝对资源路径只存在本机 checkpoint，不写公开文档或 GitHub。
- 所有新文案补中英文。

## 8. 测试与真实素材验收

测试层次：

1. 纯单元测试：跟踪、接触段、遮挡、第二名冲突、质量加权特征、命名传播、配置验证和跨项目分组。
2. SQLite 测试：旧库迁移、只读连接无副作用、自动/人工优先级、事务回滚。
3. FFmpeg 集成：有/无原声、静音、不同分辨率/fps、三种封面、自定义图、三种 BGM、本地音乐、取消和重试。
4. Flutter 测试：身份命名、项目多选、导出设置传递、错误展示。
5. 打包测试：Pose 模型、封面资源、BGM、许可证与运行时查找路径；DMG 在 arm64/x86_64 runner 构建并校验。

本地素材只用于验证，不进 Git。参考成片按 12 个命名目录提供弱人物标签，但不能把同一条进球的相邻帧拆到训练和测试两侧。按成片/原始进球事件隔离；需要精确触球真值时另行人工标注接触时间和投篮者。

分别报告：最后触球者 top-1、本场身份归属、两者联合正确率、低置信度拒判覆盖率和复核成本。未获得人工真值的项目只报告运行结果，不报告准确率。原视频仅用代理、抽帧和缓存，测试片段规模逐步扩大。

## 9. 发布、隐私与许可

- 发布功能分支和 macOS 预发布标签，不自动合并 `main`。
- DMG 默认 ad-hoc 签名且未公证；发布说明明确首次打开方式，不伪装成 Apple 已公证。
- 校验 Release 实际资产、SHA-256、`hdiutil verify`，并在可用 runner 做安装后启动检查。
- 真实视频、人物图片、特征原型、私人姓名映射、标注和本机路径不得提交。
- Ultralytics 代码及权重的再分发遵循其当前许可要求。发布前补充对应许可文本/NOTICE；不静默把项目根 MIT 许可证改成其他许可证。若某项权利未满足，则不把该项打进公开二进制。
