# macOS 二次开发实测与 Review 记录

日期：2026-11-23  
范围：`feature/macos-player-identity-enhanced-export`，目标修订版 `v0.1.16-macos.2`。  
本文记录实际观测、诊断修正和仍需人工决定的事项，不是整场识别准确率证明。

| --- | --- | --- |
| macOS | Flutter 界面、本地 Python Engine、YOLO 检测与 Pose，分别构建 Apple Silicon 和 Intel DMG | 预发布，ad-hoc 签名，未公证 |

## 2. 识别模型的真实含义

当前没有足够、隔离的标注数据训练一个可靠的通用“无号码球员识别器”。因此没有虚构训练结果，而是落地了可运行、可复核的同场模型：

1. 使用现有篮球检测模型保留球与篮筐轨迹，使用 YOLO Pose 提取人物和手腕；
2. 找进球前最后具有持续接触和释放证据的人，而非离篮筐最近的人；
3. 从衣服、裤鞋、肤色、发型和弱脸型区域提取数值特征，按可见质量聚合；
4. 在本场建立增量匿名原型，证据不足时拒判并进入人工复核；
5. 姓名只在用户确认后传播；跨天只按确认姓名合并，不自动比较人脸或外观。

## 3. 原片诊断修正

### 3.1 坐标比例

早期整场诊断出现 `0/143`，原因是输入检测已经使用 1920×1080 原片坐标，却又传入 `--proxy-scale 2`，篮筐位置被重复放大。改用正确的 `--proxy-scale 1` 后，三个人工诊断片段均检测到进球事件。这是诊断命令错误，不能将早期 `0/143` 当作生产扫描召回率。

### 3.2 时间标签

早期根据代理片段抽帧判断橙色无袖球员的出手时间不够可靠。后续直接核验原片，以原片时间为准：约 1182.812 秒触球、1183.012 秒释放。局部轨迹 ID 只在诊断窗口内有效，不是持久人物 ID。

### 3.3 长距离误关联

曾在约 59 秒处把远处误检关联为同一篮球。已加入运动速度约束，同时保留反弹和反向运动，不以“球必须一直向下”过滤轨迹。

## 4. 三样本真值与最终观测

样本是人工选择的三个进球，不包含未进球或整场全部事件，不能计算整场准确率、召回率或误报率。人工真值来自原片叠加核验。

| 匿名人物 | 人工轨迹 | v3 触球轨迹 | 原片触球 / 释放 | 最终身份处理 |
| --- | --- | --- | --- | --- |
| 白衣蓝裤 | `track_0001` | `track_0001` | 1025.863 / 1026.196 秒 | 新匿名身份，待命名与复核 |
| 灰色无袖 | `track_0007` | 未形成候选 | 无可靠时间输出 | 较长轨迹缺失，仍需人工处理 |
| 橙色无袖 | `track_0006` | `track_0006` | 1182.812 / 1183.012 秒 | 上衣区域冲突，拒绝与白衣身份自动合并 |

基线 v1 的自动触球覆盖为 1/3，该次与人工轨迹一致；自动身份覆盖和联合自动识别均为 0/3。

最终 v3 的自动触球、自动身份、联合自动识别覆盖均为 0/3，三个事件全部需要复核。这里有两项独立于自动指标的人工核验观察：白衣和橙衣的待复核触球候选均匹配人工轨迹，灰衣仍没有触球候选。不能把这两个待复核候选算作自动成功。

首次诊断复核会话上限为 1538 秒，包含工具运行和交叉核验，不是纯人工点击耗时，也没有每个事件的独立耗时。

## 5. 两项保守修复

### 5.1 短断帧接触支持

真实白衣样本在 1025.663 和 1025.863 秒有实测接触，中间两帧缺球，旧逻辑因此不生成候选。现仅在前后都有实测接触且间隔不超过 200 ms 时桥接缺口：

- 不向前缘或后缘外推；
- 仍要求至少 50 ms 接触支持、释放距离和 450 ms 释放窗口；
- 超过 200 ms 的缺口仍拒绝；
- 桥接结果带 `bridged_detection_gap=true` 和 `needs_review=true`。

灰衣样本属于更长轨迹缺失，没有套用此修复制造命中。

### 5.2 服装区域冲突拒判

原片复测发现，橙衣与白衣在上衣区域不同，但总外观距离被其他相似区域稀释，导致错误自动关联到同一匿名原型。现对具有足够可见质量的上衣、裤子和鞋子增加区域一致性检查：当自动匹配的加权平均值掩盖可靠服装冲突时，取消自动身份归属，保留候选供复核，不把新外观写入该原型。

这是一项防误关联保护，不代表已解决所有相似服装、换视角或遮挡问题。阈值仍需要更多按事件隔离的真值校准。

## 6. 整场扫描不能当作准确率

使用正确坐标比例精化 143 个粗候选后，输出 43 个精化候选，全部为 `ambiguous`：其中 `review=32`、`high=11`，42 个有完整穿筐几何，自动导出合格数为 0，耗时 304.134 秒。

这些数字只描述算法候选和置信状态。43 不等于 43 个真实进球；未建立整场人工真值前，不报告整场准确率或误报率。参考成品目录只作为弱参考，文件名不能证明剪辑前的最后触球帧。

## 7. 数据与事务边界

- 原视频、抽帧、人工真值、局部轨迹、外观特征和诊断脚本只保留在本地工作区，不上传公开仓库；
- 同场身份原型、事件和自动归属在同一事务中入库，避免只写入其中一部分；
- 原型版本不兼容时必须重跑身份分析，不能把旧模型冒充新算法结果；
- 跨项目导出使用只读快照，不批量修改历史项目；
- 姓名、照片和生物识别不是同一概念：当前模型不保存人物照片，也不做跨天身份匹配。

## 8. 发布与权利边界

- 功能分支和 macOS 预发布标签已用于交付，不合并 `main`；
- DMG 使用 ad-hoc 签名且未公证，首次打开可能有 Gatekeeper 警告；
- 没有发布 OSS 自动更新通道，不能宣称应用内自动更新已开通；
- Ultralytics / YOLO Pose 按 AGPL-3.0 提供对应声明；商业分发需评估企业许可或开源义务；
- 原篮球模型权重、训练数据、历史截图的公开权利以及依赖和 FFmpeg 声明仍需逐项权利审核；源码公开检查通过不等于这些权利已获确认；
- Apple Silicon 安装包在本机执行过随包 Python 与两个模型的加载检查；Intel 包因本机 Rosetta 不可用未在本机运行，CI Intel runner 的模型检查不能替代本机 Intel 验证；
- macOS 可能把带连字符的构建版本规范化显示，例如 `0.1.16-macos.1` 在 bundle 中显示为 `0.1.16.1`，挂载核验需同时记录标签和实际 bundle 版本。

## 9. 需要用户 Review 的决定

1. 当前实验性身份识别在 API 中默认开启。是否接受现阶段的计算成本、保守拒判和人工复核成本，还是后续改为默认关闭？
2. 是否接受“同场匿名原型 + 人工命名传播 + 跨天按确认姓名合并”，而不追求未经验证的跨天生物识别？
3. 200 ms 短断帧桥接仍要求人工复核，是否接受这一保守策略？
4. 服装区域冲突会取消自动匹配，可能增加同一人不同视角下的复核量。是否接受宁可多复核、不自动串人的取舍？
5. 灰衣样本的长轨迹缺失尚未解决。后续应优先补标注、改善检测/姿态采样，而不是继续放宽阈值。
6. 是否长期使用项目内生成的三类循环 BGM；当前未做主观听感评审。
7. 商业或正式公开分发前，是否补充模型/训练数据权利证明、Apple Developer ID 签名与公证？
